# fitz 제품판 스택 (2026-11-28 결정)

제품판을 무엇으로 짓는지와 그 이유를 한 장에 적는다. 방향과 근거의 원문은 `docs/architecture.md`, 기존 DB를 다루는 규칙은 `docs/data-contract.md`에 있다. 이 문서와 어긋나게 바꿀 때는 이 문서를 같은 커밋에서 고친다.

## 1. 구조

```
fitz.app
  셸 (Electron main)      창, 메뉴, 서버를 띄우고 죽이기. 데이터와 Claude는 다루지 않는다
  서버 (Node 자식 프로세스)  DB, 모든 쓰기, Claude. 앱에 하나. 상태의 진실은 여기에만 있다
  화면 (렌더러, React)     그리기만 한다. 사실은 서버에 묻는다
  Claude Code (서버의 자식) 모델과 대화. DB는 서버의 도구를 거쳐서만 쓴다
```

## 2. 결정

| 층 | 선택 | 이유 |
|---|---|---|
| 셸 | Electron 45 + TypeScript. 45.5.0(Node 24.22.3, SQLite 3.54.1)에서 `node:sqlite`와 서버 테스트 통과를 확인했다(2026-11-28) | Agent SDK가 앱 안의 Node에서 그대로 돈다. Octave와 T3 Code가 같은 구성으로 배포 중이다 |
| 서버 | Electron 실행 파일을 `ELECTRON_RUN_AS_NODE=1`로 띄운 자식 프로세스 하나. 미리 번들한 파일 하나로 둔다 | 맥에 깔린 Node에 기대지 않는다. 동기식 `node:sqlite`가 창을 멈추지 않는다. 서버가 죽어도 창이 살아서 이유를 보여 준다 |
| 화면 | React + Vite, shadcn 디자인 시스템(Base UI, 프리셋 `b1VlJAwK`). 기본 컴포넌트(`app/src/components/ui/`)는 도구로 받아 고치지 않고, 배치는 `sidebar-08` 블록을 따른다. 빌드된 화면을 서버가 127.0.0.1로 준다 | 편집기(TipTap)가 React다. 이 흐름을 처음부터 세워 두면 편집기를 붙일 때 다시 짓지 않는다 |
| 화면 ↔ 서버 | HTTP(조회) + WebSocket(실시간, 쓰기 기능과 함께). 메시지 규약은 파일 하나에 닫힌 목록으로 정의하고 받을 때 검증한다 | 규약이 셸과 무관하면 화면이나 셸을 바꿔도 서버는 그대로 쓴다(Codex, Zed의 ACP) |
| 셸 ↔ 서버 | 자식 프로세스 IPC 채널. 역시 닫힌 메시지 목록 | Octave 방식 |
| DB | `node:sqlite`, 책마다 SQLite 파일 하나. 첫 마이그레이션(`user_version` 0→1)에서 WAL로 바꾼다 | T3 Code, Orca, VS Code가 WAL을 쓴다. 규칙은 `docs/data-contract.md` |
| 모델 | Claude Agent SDK 하나. 사용자 본인 구독, 수정하지 않은 Claude Code 바이너리. 서버 안의 한 파일(모델 포트)에서만 부른다 | 구독으로 쓰면 추가 비용이 없다. 대화 루프, 세션, 권한이 이미 있다 |
| Rust | PDF 가져오기 엔진에만. 별도 실행 파일 + 줄 단위 JSON(stdio) | 대화와 DB 층에서는 Rust로 얻는 속도가 없다. 별도 실행 파일이면 엔진이 죽어도 서버가 산다 |
| 테스트 | 서버는 `node:test`(Electron의 Node로도 돌린다), 앱 실행은 Playwright의 Electron 실행 | 실제 앱이 뜨는지는 진짜 Electron을 띄워야 안다 |
| 리포 | pnpm 작업 공간 하나(루트 + `app/`), 잠금 파일 하나 | 설치 한 번으로 전체가 준비된다 |
| 서버·셸 코드 실행 | 개발과 테스트에서는 `.ts`를 빌드 없이 직접 실행한다(Electron의 메인 프로세스도 `electron/main.ts`를 그대로 실행한다)(지울 수 있는 타입 문법만 쓴다, `tsconfig.json`의 `erasableSyntaxOnly`). 배포용 번들은 셸을 만들 때 넣는다 | 빌드 단계가 없어 테스트가 빠르다. Node 26과 Electron 45의 Node 양쪽에서 확인했다 |
| 규약 검증 | zod. `shared/protocol.ts`에 요청과 모양을 한 번 정의해 타입과 검증을 함께 얻는다. 서버는 받은 인자와 DB에서 읽은 행을 모두 검사한다 | 규약과 어긋난 데이터는 추측하지 않고 오류로 드러낸다 |
| 검사 명령 | `pnpm check`: 루트 타입 검사, `app/` 린트와 빌드(타입 검사 포함), 일반 Node와 Electron의 Node 테스트, 브라우저 테스트 | 실제 앱은 Electron의 Node로 돌기 때문에 양쪽에서 돌린다 |
| 테스트의 기대값 | 숫자를 박지 않고 같은 사본 DB에서 SQL로 직접 센 값과 비교한다 | 사본을 다시 떠서 번역 수가 늘어도 테스트가 깨지지 않는다 |

## 3. 처음부터 넣는 것 (1단계 앱)

| # | 무엇 | 왜 | 본 곳 |
|---|---|---|---|
| 1 | 서버 접속에 실행마다 새로 만든 비밀 토큰을 요구하고 `Host`/`Origin`을 검사. 셸이 `/?token=…`을 한 번 열면 서버가 HttpOnly 쿠키로 바꾸고 주소에서 토큰을 지운다 | 127.0.0.1 포트는 이 맥의 다른 프로그램과 브라우저 페이지도 닿는다. 쿠키 방식이라 화면 코드가 토큰을 갖지 않고 WebSocket에도 그대로 실린다 | VS Code(웹 서버 모드), Jupyter |
| 2 | 서버 관리(`electron/server-process.ts`): 빈 포트, 준비 신호 확인, 충돌 시 다시 시작(5분 안에 3번이면 오류 창을 띄우고 끝), 종료는 요청 → 5초 → 강제, 셸이 사라지면 서버 스스로 종료 | 빈 창과 남겨진 서버를 막는다 | T3 Code, Octave, VS Code |
| 3 | 포트·토큰·경로는 환경 변수나 명령 인자가 아니라 셸과의 IPC 채널 첫 메시지로 서버에 전달(`shared/shellChannel.ts`). 처음 계획한 별도 통로(fd 3) 대신 이미 있는 채널을 쓴다 | 나중에 Claude 프로세스가 환경 변수를 물려받아도 토큰이 새지 않는다 | T3 Code(fd 3), Octave(IPC 채널) |
| 4 | 화면 보안: `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, preload 없음(화면이 셸에 요청할 것이 아직 없다), CSP, 다른 주소로 이동과 새 창 차단, 권한 요청 거절 | 처음엔 공짜, 나중엔 비싸다 | VS Code, T3 Code, Orca |
| 5 | 규약의 첫 인사에 버전 번호. 안 맞으면 바로 오류 | 셸·서버·화면이 어긋난 것을 바로 안다 | Codex, herdr |
| 6 | 스냅샷에 `{bootId, revision}` | 서버 재시작과 재접속을 같은 경로로 처리한다 | herdr |
| 7 | 컴파일 캐시, 창은 배경색을 칠하고 준비되면 표시, 시작 시간 측정 지점 | 첫 실행이 빨라지고 수치로 잴 수 있다 | T3 Code, VS Code |
| 8 | DB는 읽기 전용 옵션으로 열고, 준비된 쿼리를 재사용 | 1단계의 약속(읽기 전용)을 코드로 지킨다 | — |

## 4. 나중에 넣는 것 (쓰기와 Claude가 들어올 때)

## 5. 하지 않는 것과 다시 볼 조건

| 하지 않는 것 | 이유 | 다시 볼 조건 |
|---|---|---|
| Tauri | 얻는 것은 앱 크기(57MB 대 323MB)뿐이고, Node 서버를 단일 실행 파일로 묶어 넣고 정리하고 서명해야 한다. opcode는 이 길에서 Agent SDK를 포기했다 | 배포해서 앱 크기가 문제가 될 때, Agent SDK를 Tauri에 붙인 검증된 사례가 생길 때 |
| Swift 네이티브 화면 | 화면과 편집기를 전부 새로 짓는다 | 맥 앱다운 느낌이 핵심 가치가 될 때. 규약이 셸과 무관하므로 서버는 그대로 쓴다 |
| pi | API 키 과금이 되고 세션 보관과 권한을 직접 만든다 | 로컬 모델이나 다른 회사 모델을 붙일 때 모델 포트 뒤의 두 번째 연결부 후보 |
| Rust 코어 | Agent SDK가 TypeScript·Python뿐이고, 대화 시간은 모델 응답 대기라 속도 이득이 없다. 앱 로직을 다시 써야 한다 | Rust용 Agent SDK가 생길 때 |
| `utilityProcess`로 서버 띄우기 | Octave와 T3 Code가 `ELECTRON_RUN_AS_NODE` 방식으로 배포 중이다. 충돌 보고와 고아 방지는 3절의 2번으로 메운다 | 서버 충돌 원인을 알기 어렵거나 남겨진 서버가 실제로 생길 때 |

## 7. 측정 (2026-11-28, 이 맥, 개발 실행 `electron .`, 사본 DB: 장 26 / 단락 824)

| 무엇 | 값 | 어떻게 쟀나 |
|---|---|---|
| 창이 표시될 때까지 | 325 ~ 394ms (6번 중 5번), 한 번은 2,309ms | 셸이 찍는 `window shown N ms after launch` (프로세스 시작부터) |
| 실행부터 책이 화면에 보일 때까지 | 500 ~ 616ms (6번 중 5번), 한 번은 2,509ms | Playwright가 앱을 띄운 때부터 첫 단락이 보일 때까지 |
| 장을 눌러 108단락이 다 그려질 때까지 | 37 ~ 62ms | 클릭부터 마지막 단락이 보일 때까지, 6번 |
| DB 열기 | 5.8ms | Electron 45의 Node에서 `openBook` 한 번 |
| 장 목록 조회 | 중앙값 0.64ms | 50번 |
| 가장 큰 장(153단락) 조회와 검증 | 중앙값 0.57ms, 최대 3.49ms | 50번 |

- 한 장을 통째로 그려도 62ms 안이라, 보이는 부분만 그리는 기법은 아직 필요 없다.
- 2초가 넘은 한 번(두 번째 실행)의 원인은 알아내지 못했다. 다시 재서 반복되는지 봐야 한다.
- 서명된 설치본에서는 값이 달라질 수 있다. 배포 빌드를 만들 때 다시 잰다.
