# 검수(Review) — 스캔과 추출된 원문을 대조해 고치는 화면

무엇을 하는 화면인지, 지킬 규칙, 만드는 순서를 적는다. 규칙의 출처는 프로토타입(브랜치 `minkyojung/build-ocr-translation-editor`)의 코드와 테스트이고, 2026-11-28에 읽었다: `README.md`의 검수 절, `app/src/features/review/`, `app/e2e/review.spec.ts`(20개), `server/commands.mjs`의 구조 명령과 그 테스트. 슬라이스 1~4를 모두 만들었다(2026-11-28). 바꿀 때는 이 문서를 같은 커밋에서 고친다. 계획과 달라진 것과 프로토타입과 다르게 한 것은 §10에 적었다.

## 1. 무엇을 하는 화면인가

추출된 단락 하나하나를 스캔한 쪽 이미지와 대조해서 틀린 곳을 고치고 "확인됨"을 표시한다. 사람이 잡아야 하는 것은 다섯 가지다.

| 잡을 것 | 고치는 방법 | 슬라이스 |
|---|---|---|
| OCR 오탈자 | 원문을 그 자리에서 고침 | 1 |
| 단락 종류(제목, 인용, 캡션, 시) | 종류를 바꿈 | 1 |
| 기울임(텍스트 층에 없음) | 원문 편집기에서 기울임 | 1 |
| 잘못 나뉜 단락 | 나누기, 합치기 | 3 |
| 화보 쪽의 캡션(파이프라인이 버림) | 빈 쪽에 캡션 추가 | 4 |
| 자리를 못 찾은 저자 주 | 단락을 골라 연결 | 뒤 (주석 기능과 함께) |

## 2. 화면

```
사이드바                 | 스캔 (왼쪽 칸)        | 단락 목록 (오른쪽)
 책                      |  ‹ p. 12 ›            |  p. 12
 단계: Review · Translate |  [쪽 이미지]          |  ☑ Paragraph  When he arrived…
 장 목록 (확인 수/단락 수) |   └ 고른 단락의 상자  |  ☐ Quote      "The banana…"
```

| 규칙 | 출처 |
|---|---|
| 단계는 Review와 Translate 둘이고 사이드바에서 바꾼다. 앱은 Translate로 열린다(마지막 단계를 기억하는 것은 뒤에). 장 목록의 수는 단계에 따라 바뀐다: Review는 확인 수 / 단락 수, Translate는 번역 수 / 단락 수 | `docs/agent.md`(프로토타입) 배치 결정 |
| 목록은 쪽 번호 머리(`p. N`) 아래에 단락을 묶는다. 머리는 `pageStart`가 바뀌는 곳마다 붙는다 | `SegmentList.tsx` |
| 단락을 고르면 스캔이 그 단락의 `pageStart` 쪽으로 가고, 그 단락의 상자가 이미지 위에 그려진다. 상자가 화면 밖이면 가운데로 온다 | `ReviewView.tsx`, `PageViewer.tsx`, 테스트 15 |
| 스캔에서 쪽을 넘기면 그 쪽에 걸친 첫 단락(`pageStart ≤ n ≤ pageEnd`)이 골라진다 | `ReviewView.tsx` `changePage`, 테스트 2 |
| 넘긴 쪽이 다른 장이면 그 장으로 바뀐다. 장은 `[startPage, 다음 장의 startPage)` 범위다 | `lib/pages.ts`, 테스트 16 |
| 장 안인데 단락이 없는 쪽이면 선택이 비고 "이 쪽에는 단락이 없습니다"가 뜬다 | 테스트 16 |
| 상자는 쪽 크기에 대한 비율(0~1)이라 이미지 크기와 무관하다. 두 쪽에 걸친 단락은 쪽마다 상자가 하나씩이다. 상자가 없는 단락은 그리지 않는다 | `db/schema.sql` `segment_box` |
| 쪽 번호는 인쇄된 번호다. 앞부분(서문 등)은 0이나 음수다. 이미지 파일은 PDF 순번으로 이름이 붙는다 | `page.page_no`, `pdf_index` |

## 3. 단락 한 줄

| 보이는 것 | 규칙 |
|---|---|
| 확인 체크 | 누르면 `verified`를 바꾼다. 확인된 단락은 고르지 않았을 때 흐리게 보인다 |
| 종류 | 고른 단락은 메뉴로 바꾼다. 다섯 가지: Paragraph, Heading, Quote, Caption, Verse |
| `→ p. N` | 단락이 다음 쪽으로 넘어갈 때 |
| 고친 표시(점) | `ocr_text`가 있고 지금 원문과 다를 때. 올리면 원래 추출본과의 단어 단위 차이를 보여 준다 (슬라이스 2) |
| 원문 | 누르면 그 자리에서 편집한다. 커서는 누른 글자에. 헤더·체크·종류를 누르면 고르기만 한다 |

**편집**: 번역 화면과 같은 편집기를 쓰되 문단은 하나뿐이다. Enter·⌘Enter·다른 곳 클릭은 저장, Esc는 버림, Tab·Shift-Tab은 저장하고 이웃 단락. 저장은 편집을 시작할 때의 버전을 보낸다. 치던 글은 임시본으로 남는다.

**키** (편집 중이 아닐 때)

| 키 | 동작 |
|---|---|
| ↓ / j, ↑ / k | 다음 / 이전 단락 고르기 (끝에서 멈춤) |
| Space | 고른 단락의 확인 표시 바꾸기 |
| Enter | 고른 단락 편집 시작 (커서는 끝) |
| ⌘Z / ⌘⇧Z | 책의 되돌리기 / 다시 하기 |
| ⌘I | 스캔 칸 보이기 / 숨기기 |

## 4. 구조 명령 (슬라이스 3, 4)

모두 `server/commands.ts`의 명령으로, `ops`에 역방향과 함께 남는다(프로토타입과 같은 이름, 같은 인자 모양).

| 명령 | 하는 일 | 역방향 | 지킬 경계 |
|---|---|---|---|
| `splitSegment {id, offset}` | 커서 자리에서 둘로 나눈다. 자른 곳의 공백은 버린다. 뒤쪽은 같은 종류, 쪽은 앞쪽의 `page_end`, 확인 안 됨, `ocr_text` 없음. 상자는 앞쪽 것을 그대로 복사한다 | `unsplit` | 한쪽이 비면 거절(400). 번역문은 앞쪽에 남는다. 다시 하기는 같은 뒤쪽 id를 쓴다 |
| `mergeWithNext {id}` | 다음 단락을 빈칸 하나로 이어 붙인다. `page_end`는 다음 것, 확인은 풀린다. 상자는 쪽별로 합친다 | `unmerge` | 장의 마지막 단락이면 거절. 되돌리면 다음 단락이 원래 id와 번역문 그대로 돌아온다 |
| `insertSegment {chapterId, afterIdx, kind, text, pageNo}` | 그 자리에 단락을 넣는다. `ocr_text` 없음, 상자 없음 | `deleteSegment` | 빈 글이면 거절. 다시 하기는 같은 id |
| `deleteSegment {id}` | 단락을 지운다. 화면에 버튼은 없고 넣기를 되돌릴 때만 쓰인다 | `insertSegment` | 주석이나 댓글이 붙은 단락은 거절 |

- 순서 번호(`idx`)는 `(chapter_id, idx)`가 UNIQUE라서 음수를 거쳐 옮긴다. 순서만 바뀌는 것은 단락 버전을 올리지 않는다(계약 문서 §3).
- 나누기·합치기는 프로토타입에서 주석과 댓글도 함께 옮긴다. 새 앱에는 아직 주석·댓글 명령이 없지만 기존 책에 행이 있으므로(주석 161, 댓글 13), 이 명령들은 처음부터 그 행들을 옮긴다.
- 화면은 구조 명령 뒤에 장의 단락과 장 목록을 다시 불러온다.

## 5. 서버에 더할 것

| 무엇 | 내용 |
|---|---|
| 규약 | `Segment`에 `ocrText`(없으면 null)와 `boxes`(`{pageNo, x0, y0, x1, y1}` 목록). 요청 `listPages` → `{pageNo, pdfIndex, image}` 목록(PDF 순번 순서) |
| 쪽 이미지 | `GET /pages/<파일>`. 다른 요청과 같이 토큰·Host·Origin을 검사한다. 쪽 폴더 밖은 주지 않고 PNG만 준다. 책 내용이므로 캐시는 `private` |
| 설정 | 셸이 서버에 쪽 폴더(`pagesDir`)를 알려 준다. 개발에서는 `dev-data/out/pages` |
| 임시본 | 원문 쪽 임시본도 둔다: `draft`에 `side`를 더한다(책 버전 3). 지금은 번역문 것만 있다 |
| 명령 | 슬라이스 3에서 `splitSegment`·`unsplit`·`mergeWithNext`·`unmerge`, 4에서 `insertSegment`·`deleteSegment` |

원서 PDF와 쪽 이미지는 기기를 떠나지 않는다(출판 계약). 이미지는 127.0.0.1의 이 서버가 이 앱의 창에만 준다.

## 6. 화면에서 쓰는 shadcn 컴포넌트

기본 컴포넌트는 `shadcn add`로 받아 고치지 않는다.

| 자리 | 컴포넌트 | 이유 |

| 확인 체크 | `checkbox` | — |
| 단락 종류 | `select` (고른 단락), `badge` (그 밖의 단락, 기본 종류가 아닐 때) | 하나를 고르는 값이다 |
| 쪽 넘기기 | `button` (아이콘) | 이미 있다 |
| 단축키 표시 | `kbd` | — |
| 고친 곳 비교 | `popover` | 슬라이스 2 |

## 10. 만든 결과 (2026-11-28)

브라우저 테스트 `e2e/review.spec.ts` 19개, 서버 테스트 `server/structure.test.ts` 14개가 이 문서의 규칙을 확인한다.

**프로토타입과 다르게 한 것**

| 무엇 | 프로토타입 | 새 앱 | 이유 |
|---|---|---|---|
| 합치기가 옮기는 것 | 주석과 댓글만 | 단락을 가리키는 모든 행(주석, 댓글, 관계, 이전 번역, 복습 카드·고른 말, Claude 제안). 되돌리면 모두 제자리로 | 프로토타입은 뒤 단락에 관계가 있으면 합치기가 실패했고, 복습 카드와 제안은 지워졌다 |
| 합치기의 번역문 | 앞 단락 것만 남김 | 앞 단락의 문단들 다음에 뒤 단락의 문단들. 상태는 둘 중 낮은 것, 한쪽만 번역됐으면 초벌 | 번역된 두 단락을 합치면 한쪽 번역이 사라졌다 |
| 원문의 댓글 위치 | 합칠 때 옮기기만 함 | 원문 쪽 댓글은 주석처럼 위치도 옮김(번역문 쪽 댓글은 그대로) | 원문 앞에 다른 단락의 글이 붙으므로 |
| 되돌릴 때의 원문 | 문서를 다시 써서 넣음 | 저장돼 있던 문자열 그대로 넣음 | 같은 내용이라도 글자 모양이 바뀌었다(파이썬이 쓴 JSON의 공백) |
| 빈 원문 저장 | 받음 | 거절(400) | 단락은 합쳐서 없앤다. 실수로 비우는 것을 막는다 |
| 지우기 | 서버에 있음 | 서버에 있지만 화면에 내놓지 않음 | 넣기를 되돌릴 때만 쓰인다 |

**계획에서 바뀐 것**

- "단락 없음" 안내는 목록 위에 고정했다(목록 안에 붙이면 쪽 번호 머리가 "Add caption" 버튼을 가렸다).
- 나누기는 편집 중인 단락의 머리에 있는 "Split at caret" 버튼으로 한다. 친 글이 있으면 먼저 저장하고, 저장이 거절되면 나누지 않는다.
- 합쳐서 사라진 단락의 임시본은 지운다(임시본은 책의 일부가 아니다).

**알려진 작은 문제**

- 원문을 편집으로 열면 줄바꿈 위치가 한두 단어 달라질 때가 있다(읽기 화면과 편집기의 공백 처리 차이로 보인다). 동작에는 영향이 없다.
